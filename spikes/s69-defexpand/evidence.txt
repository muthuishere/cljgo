A. defexpand'd name used as a VALUE:
   (macroexpand-1 '(dbl 4)) => (do (clojure.core/* 2 4))
   (dbl 4)                  => 8    ; direct call: fine
   (map dbl [1 2 3])        => THREW: wrong number of args (1) passed to: user/dbl
   (apply dbl [4])          => THREW: wrong number of args (1) passed to: user/dbl
   dbl                      => #object[user/dbl]
   (fn? (deref (var dbl)))  => true

B. can a name be BOTH a macro and a fn value?
   after (defmacro mname ...): (mname 1)   => 2
   after (defn mname ...):     (mname 1)   => 0   ; the macro is GONE
   (map mname [1 2 3])                     => (0 1 2)
   ; whichever def runs last wins. There is no 'both'.

C. `definline` today (metadata stored, no call-site inlining):
   (dsqr 5)          => 25
   (fn? dsqr)        => true    ; it IS a value
   (map dsqr [1 2 3])=> (1 4 9)
   (:inline (meta (var dsqr))) present? => true
   ; the var carries both the fn and the inline template. THIS is the
   ; only shape that satisfies ADR 0107 rule 4.

D. the guarded prototype keeps a fn — under a DIFFERENT name:
   (gdbl 4)              => 8
   (map gdbl-fn [1 2 3]) => (2 4 6)
   (map gdbl [1 2 3])    => THREW: wrong number of args (1) passed to: user/gdbl
   ; two names is not what ADR 0107 promises. The name split is an
   ; artefact of the macro mechanism, not of the semantics.
