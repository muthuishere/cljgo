# G5012 — maven artifact checksum mismatch

The bytes cljgo downloaded for a Maven artifact do not hash to what was
expected — either the repository's own `.sha1` sidecar, or the `:mvn/sha256`
recorded in `build.lock.edn`.

```
error: maven artifact checksum mismatch for medley/medley 1.4.0 (jar)
       expected sha256:1f0e…  (build.lock.edn)
       found    sha256:9ab3…
help: run `cljgo cache clean` and resolve again
help: run `cljgo explain G5012`
```

## What it means

The lock is the real integrity story: it records the sha256 of the exact bytes
that were resolved when the lock was written, and every later resolve
re-verifies against it. The repository's `.sha1`, when served, is a cheap
corroboration checked at download time.

A mismatch means one of: the cache entry was modified after it was written, the
repository re-published the same coordinate with different bytes (which it must
never do), or the download was corrupted or intercepted.

## What to do

- `cljgo cache clean`, then resolve again. If it now matches, it was a bad
  cache entry.
- If it mismatches again, the *remote* changed. Do not "fix" it by deleting the
  lock line — find out why an immutable coordinate moved.
