# G5016 — unsupported dependency version syntax

A `{:mvn/version "…"}` you wrote in `build.cljgo` uses a version *syntax*
cljgo does not support. It is refused **before** any repository is contacted,
so the error names your declaration rather than blaming a repository for not
serving something that was never a fixed coordinate.

```
error: dependency "some/lib" declares a -SNAPSHOT version, which cljgo does not support
  expected: a fixed published version, e.g. "1.1.230"
  found:    1.0-SNAPSHOT
help: pin one published release, e.g. (dep b "some/lib" {:mvn/version "1.2.3"})
help: or depend on it via :git — a ref is a fixed identity too
help: run `cljgo explain G5016`
```

## The refused shapes

| you wrote | why |
|---|---|
| `1.0-SNAPSHOT` | mutable identity: the same coordinate serves different bytes over time, which a content-verified `build.lock.edn` cannot express |
| `[1.0,2.0)`, `(,1.0]` | a version range needs a solver; cljgo has none, by design |
| `LATEST`, `RELEASE` | floating meta-versions: the build is not reproducible |
| `${something}` | a POM property placeholder has no meaning in a declaration |
| `""` | no version at all |

The same rule judges transitive edges inside a POM, where the refusal is
reported as [G5011](G5011.md) instead — one implementation, two call sites, so
a shape cljgo refuses in your file is refused in a dependency's POM too.

## What to do

Pin a published release. `cljgo` deliberately has no "resolve me something
recent" mode: every dependency in a lock file is one immutable set of bytes
verified by sha256.
