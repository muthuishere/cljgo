# G5024 — cannot resolve real-path (missing path or symlink cycle)

`cljg.io/real-path` resolves every symlink in a path and returns an absolute,
cleaned result — backed by Go's `filepath.EvalSymlinks`. Unlike
`cljg.io/absolute` (`filepath.Abs`, purely lexical), `real-path` touches the
filesystem, so it can fail in ways `absolute` cannot:

1. **The path does not exist.** `EvalSymlinks` stats every component; a
   missing file or directory is an error, not a value to fake. Returning the
   unresolved input here would silently defeat the whole point of
   canonicalising a path — a caller could no longer tell "canonical" from
   "unresolved".
2. **A symlink cycle.** `EvalSymlinks` returns `ELOOP` rather than looping
   forever. This is what makes `real-path` usable as a directory-walk cycle
   guard: canonicalise each directory you visit and refuse to revisit a
   canonical path already seen.

## Fix

- Check `cljg.io/exists?` first if the path may legitimately be absent.
- If a symlink cycle is expected input (e.g. walking untrusted directory
  trees), catch this error and treat it the same as "already visited".
