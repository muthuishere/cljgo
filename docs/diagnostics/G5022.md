# G5022 — unsupported or unmatched java.time date pattern

`cljg.date/format-pattern` and `cljg.date/parse-pattern` take a **java.time
`DateTimeFormatter` pattern** — the same string the JVM takes, so a `.cljc`
library's `:clj` branch needs no translation at all.

This error means one of three things:

1. the pattern uses a token cljgo will not approximate,
2. the pattern is malformed (a token repeated a length java.time rejects, or
   an unterminated `'…'` literal), or
3. `parse-pattern` was given input that does not match the pattern.

## Supported tokens

| Token | Meaning | Lengths |
|---|---|---|
| `y` | year | `yy` (2000-based), `yyyy` |
| `M` | month | `M`, `MM` numeric · `MMM` `Jul` · `MMMM` `July` |
| `d` | day of month | `d`, `dd` |
| `E` | day of week | `E`…`EEE` `Fri` · `EEEE` `Friday` |
| `H` | hour, 0–23 | `H`, `HH` |
| `h` | hour, 1–12 | `h`, `hh` (pair with `a`) |
| `m` | minute | `m`, `mm` |
| `s` | second | `s`, `ss` |
| `S` | fraction of a second | `S`…`SSSSSSSSS` |
| `a` | AM/PM | `a` |
| `X` | offset, `Z` when zero | `X` `+01` · `XX` `+0100` · `XXX` `+01:00` |
| `Z` | offset, never `Z` | `Z`…`ZZZ` `+0100` |

Anything else in `'single quotes'` is a literal; `''` is a literal quote.

## Refused tokens, and why

These are refused rather than approximated, because an approximation reads as
success:

`G` era · `Q` quarter · `D` day-of-year · `w` week-of-year · `W` week-of-month
· `F` day-of-week-in-month · `k` clock-hour 1–24 · `K` hour-of-am-pm 0–11 —
cljgo's calendar has no exact equivalent.

`Y` is the **week-based** year and is not the calendar year — use `yyyy`.
`u` is the proleptic year and differs from `yyyy` only before year 1 — use
`yyyy`. `z` (zone *name*) and `V` (zone ID) do not round-trip — use `XXX` or
`Z` for the offset.

The refusal happens when the pattern is compiled, never part-way through
rendering, so a program cannot emit half a timestamp.

## Locale is ENGLISH, not ROOT

`MMM`/`MMMM`/`EEE`/`EEEE` render English names. For a `.cljc` library that must
agree across hosts, pin **`Locale.ENGLISH`** on the JVM side:

```clojure
#?(:clj  (.format (DateTimeFormatter/ofPattern p java.util.Locale/ENGLISH) t)
   :cljgo (date/format-pattern t p))
```

Do **not** pin `Locale.ROOT`. ROOT has no distinct full forms and yields `Jul`
for `MMMM` and `Fri` for `EEEE`, which diverges silently on exactly the tokens
you were trying to protect.

## Parsing is stricter than formatting

`parse-pattern` refuses a pattern that cannot name a whole instant, rather than
defaulting the missing part:

- no year, month, or day → refused (a silent 1970 is worse than an error)
- `h` without `a` → refused (the meridiem is genuinely unknown)
- a parsed weekday that contradicts the parsed date → refused

A pattern carrying no offset is read as UTC.
