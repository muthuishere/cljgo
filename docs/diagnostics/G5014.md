# G5014 — offline: maven coordinate unavailable

Resolution ran with `-offline` (or with no network available) and a Maven
coordinate it needs is not in the cache, or is not in `build.lock.edn` at all.

```
error: offline: maven coordinate medley/medley 1.4.0 is not in the cache (/home/me/.cache/cljgo/mvn/3f2a…)
help: drop -offline, or run resolve with -update while online
help: run `cljgo explain G5014`
```

## The offline matrix

This is the same policy git dependencies already have — nothing new:

| state | behaviour |
|---|---|
| lock has the coordinate, cache warm | resolves, no network, tree hash verified |
| lock has the coordinate, cache cold | **G5014** |
| no lock entry at all | **G5014** — it cannot be resolved without a remote |

## What to do

Resolve once while online to populate the cache and the lock, then offline
builds work from the cache alone. A `vendor/<name>/` directory is the air-gap
hatch: it overrides the cache entirely, under the same lock hash check.

Note that the **purity report** — which of a library's namespaces are usable
and which need Java — is recorded in the lock, so it can be printed offline,
before a byte is fetched.
