# G5026 — file loaded but did not define the required namespace

`require` found the file for a namespace, read it, and evaluated it — and the
namespace still does not exist afterwards. The file is present; it simply
never declared the name that was asked for.

## Why this happens

Almost always one of two things:

- **The file has no `(ns …)` form.** A script of bare top-level forms is a
  perfectly good thing to `cljgo run`, but it cannot be `require`d, because
  `require` resolves a *namespace* and nothing in the file creates one.
- **The `ns` form disagrees with the path.** `src/demo/core.cljc` must
  declare `(ns demo.core)`. Requiring `demo.core` locates the file by
  convention, so a mismatched declaration loads the file and interns a
  different namespace.

Underscores and hyphens are part of that convention: the file
`demo/my_util.cljc` declares `(ns demo.my-util)`.

## What this replaces

The old message was:

```
namespace demo.core not found after loading its source
```

which names the wrong condition. "Not found" reads as *the file is missing*,
so the reader goes hunting for a file that is sitting right there, correctly
located. The problem is never the lookup — it is that the file did not define
what it was supposed to.

Found by the toolnexus Clojure port while confirming the fix for issue #182:
their reproduction turned out to be two problems wearing one error message,
and only the first was #182. The second was this.

## Fixing it

Add the `ns` form, or rename the file so its path matches the namespace it
declares. If the file is a script rather than a library — bare forms, no `ns`
— run it (`cljgo run path/to/file.cljc`) instead of requiring it.
