# R1012 — reader conditional supplies no branch for this platform

A `#?(…)` / `#?@(…)` reader conditional was read in a source file that came
out of a **Maven (Clojars) dependency**, and none of its branches is one cljgo
can select. cljgo's platform feature is `:cljgo`; `:default` also always
matches. It does **not** claim `:clj` — that is the JVM's feature, and
claiming it would deliberately pull in the very branch a portable library
fenced *away* from non-JVM hosts (ADR 0095, spike s50 finding 4).

```
error: reader conditional supplies no branch for this platform; expected one of :cljgo, :default; found :clj, :cljs at medley/core.cljc:14:3
help: run `cljgo explain R1012`
```

## Where it fires

Three shapes, all of which make something disappear silently:

1. a **top-level** starved conditional — a whole form vanishes and the
   namespace can install with no vars;
2. one directly inside a **vector, map or set** — the collection's element
   count changes (`[a 1 b #?(:clj x)]` becomes a 3-element binding vector);
3. one nested inside a **list** with forms **after** it, which silently slide
   into its place and change the call's **arity**.
   Real case: medley 1.4.0 `core.cljc:181`,
   `(instance? #?(:clj clojure.lang.PersistentQueue :cljs …) x)`. Elided, that
   reads as `(instance? x)` and the compiler reported
   `wrong number of args (1) passed to: clojure.core/instance?` — an error that
   named neither the conditional nor the library.

```
error: reader conditional supplies no branch for this platform, and eliding it would change the shape of the enclosing list; expected one of :cljgo, :default; found :clj, :cljs at medley/core.cljc:181:14
```

It deliberately does **not** fire where the elision breaks nothing: a
**trailing** conditional in a list (`(def x #?(:clj Long/MAX_VALUE :cljs …))`
stays a well-formed `def` — real com.stuartsierra/dependency 1.0.0 — and
`(defn- f [x] #?(:clj … :cljs …))` a well-formed `defn`), a
`#?@(…)` splice (it contributes zero elements), an ns-clause fence such as
`(:import #?(:clj [java.util Date]))` (the list head is a keyword; nothing is
called), a conditional inside another conditional's body (the body is read
before a branch is selected, so it may sit in a branch cljgo would never take),
or one inside a `#_` discard, a string or a `;` comment.

## Why this is an error here and not in your own code

On the JVM, and in **your** project's code, a conditional that matches nothing
legally reads as *nothing at all* — the form is elided like a `#_` discard.
cljgo keeps that behaviour everywhere except for Maven-origin source, because
there it is a trap: a `.cljc` whose real body is `:clj`-only would install a
namespace with **no vars**, and the first call would fail somewhere else
entirely, blaming your code instead of the library.

So the consume path opts into the starved-conditional check and fails loud, at
the conditional, naming the file, line, column, and the branches that *are*
present.

## What to do

The namespace is written for the JVM only. cljgo compiles to Go and runs no
`.class` files, so there is nothing to fix in the library. Either:

- use a different namespace from the same library — run `cljgo resolve` to see
  which of its namespaces *are* usable; or
- drop the dependency and use a cljgo-native or pure-Clojure equivalent.

There is deliberately **no** `:clj` escape hatch: supplying `:clj` would read
JVM forms the Go host cannot run, and the failure would surface later and
further from its cause.
