# G5027 — unknown option in a cljg.* opts map

A `cljg.*` function was passed an options map containing a key it does not
know:

```
cljg.net.http/request: unknown option :time-out (known: :method :url :headers :query :body :json :edn :form :timeout-ms :timeout :retry :as)
help: did you mean :timeout-ms?
help: run `cljgo explain G5027`
```

## Why this is an error and not a shrug

Before cljgo v0.8.10 the misspelled key was simply ignored: `(:timeout-ms opts
30000)` fell through to the default, the call succeeded, and nothing anywhere
said the option had been dropped. That failure has **no symptom**. A timeout
that never applies still returns a correct response from a fast server, so a
whole test suite stays green while the caller's timeout budget has evaporated
— which is exactly how a dead HTTP timeout reached production in a downstream
project and survived a green suite on two hosts (issue #192, ADR 0120).

Every option in a `cljg.*` opts map changes behaviour. Ignoring one silently
is the failure mode cljgo's diagnostics doctrine exists to prevent, so the
option set of a `cljg.*` function is **closed**: what it does not list, it
refuses.

## Fix

- Read the key it suggests. The `help: did you mean …?` line fires whenever a
  known key is within two edits of what you wrote, which covers the whole
  family of `:timeout` / `:timeout-ms` / `:time-out` mistakes.
- If there is no suggestion, the message lists the complete known set — that
  list is the function's documented options and nothing else.
- **If the extra key is deliberate**, do not pass it here. Threading one map
  through several functions is ordinary Clojure, but a `cljg.*` opts map is
  the argument list of one function, not a shared context:

  ```clojure
  ;; refused — :service-name is not an option of cljg.net.http/request
  (http/request (assoc ctx :url u))

  ;; select the options out of your context instead
  (http/request (assoc (select-keys ctx [:timeout-ms :retry :headers]) :url u))
  ```

## What is NOT checked

The check is one level deep. Nested maps inside an opts map are **data**, not
options — `:headers`, `:query`, `:form` (`cljg.net.http`), `:env`
(`cljg.io/exec`, `cljg.process/spawn`) — and their keys are yours to choose.

Two `cljg.os` maps are also deliberately open: `cljg.os/job` and
`cljg.os/service` `merge` your map into the job/service record they return, so
extra keys are carried by design, not dropped.
