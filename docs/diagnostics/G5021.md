# G5021 — frozen build: `build.lock.edn` does not match `build.cljgo`

You built with `--locked` (or `CLJGO_LOCKED=1`), and the dependencies
`build.cljgo` declares are not the ones `build.lock.edn` pins.

Frozen mode makes the lock the **authority**. An ordinary `cljgo build`
notices that the declared set moved and re-pins it for you; `--locked` refuses
instead, and writes nothing.

## Why you would want that

Auto-refresh is right for a developer who just edited the manifest, and wrong
for CI. The case this exists for is a **merge**: one branch's `build.cljgo`
lands beside another branch's `build.lock.edn`, or someone edits the manifest
and forgets to commit the regenerated lock. Without `--locked` that builds
green against a dependency graph nobody reviewed.

This is not the same as `--offline`. You can be perfectly online and still
want the lock to decide — the `npm ci` / `cargo --locked` position.

## Fixing it

- **In CI**: this usually means a commit is missing. Build locally without
  `--locked`, then commit the regenerated `build.lock.edn` alongside the
  `build.cljgo` change that caused it.
- **Locally**: drop `--locked`. The build re-resolves only the declarations
  that actually moved and keeps every other pin exactly as it was.
- **No lock at all**: build once without `--locked` to generate it, and commit
  it.

The error names the declarations that diverged, so you can see whether the
manifest or the lock is the one that is behind.
