# G5013 — maven version conflict

Two dependencies in the graph require the same Maven coordinate at two
different versions. cljgo does **not** silently pick the newest (no MVS, no
solver): it names both requirers and both versions and stops — the same policy
as ADR 0052 decision 4 for Go modules.

```
error: maven version conflict for medley/medley: 1.4.0 (required by <project>) and 1.3.0 (required by hiccup/hiccup)
help: (accept-version b "medley/medley" "1.4.0")
help: run `cljgo explain G5013`
```

## What to do

Decide, in your own `build.cljgo`, which version wins:

```clojure
(accept-version b "medley/medley" "1.4.0")
```

The key for a Maven dependency is the **coordinate string** `"group/artifact"`
— the same string you pass to `dep`.

## Why not just take the newest?

Because "newest wins" is a silent decision that changes what your program runs.
The graph walk is BFS/first-wins for *identical* versions, which is
deterministic and needs no policy; a genuine *disagreement* is a decision only
you can make.
