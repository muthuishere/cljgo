# G5025 — build file defines no build entry point

The build file was found and evaluated, but it never defines `build`. A build
file describes a project by defining one function:

```clojure
(defn build [b]
  (let [app (exe b {:name "app" :main "src/demo/app.cljc"})]
    (install b app)))
```

Helper `def`s and `defn`s above it are fine and are evaluated first — but
`build` itself is the entry point cljgo calls, so without it there is nothing
to run.

## Why this happens

Usually one of:

- **The function has a different name** — `jar`, `main`, `-main`, `compile`.
  cljgo calls `build` specifically.
- **It is nested or commented out** — a `(defn build …)` inside another form
  is not a top-level `def`, so nothing interns it.
- **The file is not actually a cljgo build file.** A JVM `build.clj` written
  for tools.build defines steps like `jar` and `uber` and is not a cljgo
  build description at all. cljgo no longer claims that name (ADR 0117), so
  this should now only arise for a file genuinely named `build.cljgo` or
  `build.cljg`.

## What this replaces

Before this code, the missing entry point surfaced from inside cljgo's own
driver:

```
error: evaluating build fn: compiler error at <build-driver>:1:38:
unable to resolve symbol: build in this context
```

Every part of that was unusable. `<build-driver>` is a string cljgo
synthesizes to invoke your `build` fn, so it named a file that does not exist
and gave a column *into that nonexistent file*; your actual `build.cljgo` was
never mentioned; and "unable to resolve symbol" described cljgo's internals
rather than the one fact that mattered.

It was found by koine while black-box bisecting issue #176 — stripping a
`require` from a root `build.clj` left this error behind, which is how it
surfaced as a defect in its own right rather than an artifact of that bug.

## Fixing it

Add a top-level `(defn build [b] …)` to the build file. It receives the
builder and declares the project's artifacts.

If the file is a JVM tools.build script, it should be named `build.clj` —
cljgo does not read that name, and the two can sit side by side in a
dual-host project.
