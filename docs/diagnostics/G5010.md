# G5010 — options argument is not a map

**Message pattern:** `<fn>: options must be a map (expects {:append true},
found: <value>)`

## Cause

The trailing `opts` argument of the byte/file writers is a MAP of options:

```clojure
(io/write-bytes path data {:append true})
(st/to-file path {:append true})
```

A caller who reaches for the obvious `(io/write-bytes path data true)` is
passing `true` where a map belongs. Destructuring that with `(:append true)`
yields `nil`, so the option is silently DROPPED and the file is truncated —
exactly the opposite of what the caller asked for, with no error. G5010 turns
that silence into a named failure: a non-map (and non-nil) `opts` is rejected
at the call, before the file is opened.

`nil` remains legal — it is the no-options arity's own value.

## Example

```clojure
(io/write-bytes "log.bin" data true)   ; G5010
;; cljg.io/write-bytes: options must be a map (expects {:append true},
;; found: true)
```

## Fix

Put the option in a map:

```clojure
(io/write-bytes "log.bin" data {:append true})
```

Or drop the argument entirely to truncate:

```clojure
(io/write-bytes "log.bin" data)
```
