# G5009 — collection value in a row map

**Message pattern:** `cljg.data.cast/<verb>: column <:k> of the <row|set|where>
map is a <kind> — a column value must be a scalar SQL param (expects a string,
number, boolean, keyword or nil, found a <kind>)`

## Cause

`insert!`, `update!` and `delete!` take MAPS, not varargs — they build the SQL
and its `?` parameters themselves, one parameter per map entry:

```clojure
(db/insert! conn :t {:a "x"})                 ; insert into t (a) values (?)
(db/update! conn :t {:a "x"} {:b "z"})        ; update t set a = ? where b = ?
(db/delete! conn :t {:b "z"})                 ; delete from t where b = ?
```

Every value in those maps becomes one bound SQL parameter, and no SQL driver
accepts a Clojure vector/map/set/seq as a bound value. G5009 fires when one of
those map VALUES is a collection.

This is deliberately NOT [G5008](G5008.md): there the caller bundled the
varargs params into one collection and `apply` fixes it. Here the call shape is
correct — there is no varargs param to spread, and `apply` would fix nothing —
so the diagnosis names the column instead, and offers no fix it cannot make
good on.

## Example

```clojure
(db/insert! conn :t {:a ["x" "y"]})   ; G5009
;; cljg.data.cast/insert!: column :a of the row map is a vector — a column
;; value must be a scalar SQL param (expects a string, number, boolean,
;; keyword or nil, found a vector)
```

## Fix

Decide how that value should live in the column and pass a scalar:

```clojure
(db/insert! conn :t {:a (str/join "," ["x" "y"])})   ; a text column
(db/insert! conn :t {:a (json/write-str ["x" "y"])}) ; a JSON column
```

or spread the collection across rows:

```clojure
(doseq [v ["x" "y"]] (db/insert! conn :t {:a v}))
```

Strings, numbers, booleans, keywords and `nil` are the legal scalar values;
only Clojure collections are rejected.
